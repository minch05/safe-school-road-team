# 9주차 팀 작업 준비 (10/28~11/3)

이 문서는 팀원 각자가 **직접 개발·커밋**할 수 있도록 작업 범위와 확인 방법을 정리한 안내다. 정강태·유준서·이동한은 각자 주 2시간 30분을 기준으로 한다. 팀 공용 저장소의 현재 기본 브랜치는 Java 17·Spring Boot 3.5.6 초기 서버이며, 회원/시설/지도 모듈과 DB 연결은 아직 없다. 개인 실험 저장소의 파일이 팀 저장소에 이미 있다고 가정하지 않는다.

## 공통 시작

1. 팀 공용 저장소 `minch05/safe-school-road-team`을 clone한다. macOS/Linux는 `./gradlew test bootJar`와 `./gradlew bootRun`, Windows는 `gradlew.bat`로 실행한다. 초기 상태 확인은 `http://localhost:8081/health/setup`이다.
2. 각자 **자기 컴퓨터의 MySQL DB**를 사용한다. 팀 `compose.yaml`의 MySQL 8을 쓰려면 `.env.example`을 `.env`로 복사해 로컬 비밀번호를 설정하고 `docker compose up -d`를 실행한다. 이미 3306 포트에 MySQL이 실행 중이면 Docker MySQL을 중복 실행하지 않는다. 현재 초기 서버는 DB에 연결되지 않으므로 DB 연결 설정·의존성은 기능 개발 과정에서 추가해야 한다.
3. 작업별 브랜치에서 본인 코드를 직접 수정하고, 실행 확인 뒤 **본인 개발 커밋 1개 이상**과 PR을 올린다. `.env`, API 키, DB 암호, 공공데이터 원본 대용량 파일은 커밋하지 않는다.
4. 서비스 정책은 **12개 구 정식 지원**(강서·광진·동대문·중랑·관악·강북·구로·성북·종로·영등포·양천·중구), 그 외 구는 **자료 부족 안내를 표시하면서 이용 가능**이다. 특정 구 한 곳만 서비스 대상으로 제한하는 작업은 아니다.

## 정강태 — 회원가입 서버 (9주)

**이번 주 끝낼 최소 동작:** 회원 테이블에 가입 1건을 저장하고, 같은 아이디 재가입을 거부하며, 비밀번호를 원문 대신 해시로 저장한다.

| 순서 | 직접 개발할 것 | 확인 방법 |
|---|---|---|
| 1 | 현재 `build.gradle`과 `application.yml`을 읽고 로컬 MySQL 연결에 필요한 의존성·설정 추가 | 서버가 로컬 DB에 연결되고 비밀번호는 Git에 남지 않음 |
| 2 | 회원 저장 테이블/모델과 아이디 중복 조회 구현 | 같은 아이디 2회 가입 시 두 번째가 거부됨 |
| 3 | 가입 입력 검증과 비밀번호 해시 저장 구현 | 빈 입력 거부, DB에 비밀번호 원문 없음, 응답/로그에 원문 노출 없음 |

**시간이 모자라면:** 회원 저장·중복 거부·해시 저장까지 본인 코드로 작동하는 범위를 커밋한다. 로그인/자동 로그인은 10주 담당 작업이다. AI에는 현재 팀 프로젝트의 의존성·패키지를 먼저 읽히고 한 동작씩 요청한다.

## 유준서 — 시설 테이블·횡단보도 적재 (9주)

**이번 주 끝낼 최소 동작:** 정식 지원 구의 서울시 횡단보도 원본 일부를 본인 로컬 DB에 적재하고, 같은 원본을 다시 넣어도 중복이 생기지 않게 한다.

**원본:** 서울시 교통안전시설물 횡단보도 `OA-15554`. 개인 검토 자료의 `trafficSafetyA004AInfo` JSON은 `records` 배열이고, 주요 열은 `CRSWK_MNG_NO1`(관리번호), `HSTRY_ID`(변경 이력), `STTS`(상태), `XCRD/YCRD`(원본 좌표), `GU_CD`(구 코드)다. 원본 좌표는 위도·경도가 아니므로 좌표계 확인·변환 없이 지도에 바로 넣지 않는다. 원본 파일은 팀 저장소에 자동으로 들어 있지 않다. **중랑구 원본 표본 10건은 별도 `9주차-유준서-횡단보도-원본표본-10건.json`으로 준비했다.**

| 순서 | 직접 개발할 것 | 확인 방법 |
|---|---|---|
| 1 | 시설 테이블의 최소 필드 `kind/source/sourceId/lat/lng/district/baseDate`와 원본 ID 유일 조건 마련 | 동일 `source + sourceId`가 중복 저장되지 않음 |
| 2 | 원본의 관리번호·최신 이력·상태·좌표를 확인해 횡단보도 표본 적재 | 실제 원본 10건 이상을 로컬 DB에서 `COUNT(*)`와 종류/구 조건으로 조회 |
| 3 | 같은 표본을 두 번 적재하고 좌표 없는 행을 구분 | 2회 적재 후 건수 동일, 제외 행 수 기록 |

**시간이 모자라면:** 테이블·유일 조건·10건 적재를 먼저 작동시켜 본인 SQL/스크립트 커밋을 남긴다. 기존 개인 실험 코드 전체를 복사하는 작업은 아니다. 기준일이 원본에 없으면 오늘 날짜를 자료 기준일로 만들어 넣지 않는다.

## 이동한 — 지도 입력·후보 선 1개 (9주)

**이번 주 끝낼 최소 동작:** 출발·도착을 지도에서 선택하고, 서버로 좌표 두 쌍을 보내며, 받은 후보 경로선 1개를 표시한다.

| 순서 | 직접 개발할 것 | 확인 방법 |
|---|---|---|
| 1 | 팀 초기 웹 화면 구조 확인 후 지도 화면과 출발·도착 선택 상태 구현 | 두 점을 각각 선택·변경할 수 있음 |
| 2 | 요청값을 `start:{lat,lng}`, `end:{lat,lng}`로 구성하고 누락 입력을 막음 | 한 점만 선택했을 때 요청을 보내지 않고 안내 표시 |
| 3 | 후보 응답의 `line` 좌표로 선 1개 표시, 실패 상태 처리 | 실제 API 연결 시 선 표시. API가 아직 없으면 같은 형식의 **개발용 예시 응답**으로 화면만 검증하고 예시임을 표시 |

**시간이 모자라면:** 두 좌표 선택·누락 방지까지 본인 HTML/JS 커밋을 남기고, 선 표시는 남은 작업으로 명시한다. 현재 팀 초기 서버에는 지도/경로 API가 없으므로 민채의 후보 API가 합쳐지기 전 실제 경로가 나온다고 표시하지 않는다.

## 화면·서버·DB 연결 약속

| 연결 | 최소 값 | 주의 |
|---|---|---|
| 지도→후보 서버 | `start:{lat,lng}`, `end:{lat,lng}` | `lat`은 위도, `lng`는 경도. 한 점 누락/범위 밖/외부 API 실패를 구분 |
| 후보 서버→지도 | `candidateId`, `line:[{lat,lng}]`, `distanceM`, `durationSec` | 후보 0개/1개/복수에 대응. 정확한 URL·응답 JSON은 서버 구현 PR에서 확정 |
| 원본→시설 DB | `kind`, `source`, `sourceId`, `lat`, `lng`, `district`, `baseDate` | 같은 원본 ID 중복 방지. `0건`과 `자료 미적재`를 혼동하지 않음 |

## 민채가 전달·통합할 것

- 유준서에게 원본 `OA-15554`의 출처와 준비된 **중랑구 표본 10건**을 전달한다. 원본 전체 파일은 팀 Git에 넣지 않는다.
- 발급된 지도/TMAP 키의 **로컬 설정 방법**만 필요한 담당자에게 전달한다. 값 자체는 문서·Jira·Git에 쓰지 않는다.
- 세 PR이 올라오면 병합·충돌 해결·첫 사용자 흐름 연결은 민채의 별도 개발 작업으로 처리한다. 팀원 담당 구현을 대신 작성하지 않는다.
