## 공통: API 한눈에 보기

| 요청 | 하는 일 | 성공 | 실패 |
|---|---|---|---|
| `POST /api/routes/evidence` `{start, end}` | 후보별 근거(안전 점수 없음) | 200 | 400 좌표 오류 · 503 TMAP 실패 |
| `POST /api/routes` `{start, end, candidateId, name}` | 고른 후보 확정·저장. 지점은 서버가 다시 계산 | 201 `{id, pointCount, guideSource}` | 400 이름·후보 오류 · 401 · 422 지점 없음 · 503 |
| `GET /api/routes` | 내 저장 경로 목록 | 200 `{routes:[…]}` | 401 |
| `GET /api/routes/{id}` | 상세: 지점·기본 안내문 | 200 | 404 없음·남의 경로(구분하지 않음) |
| `GET /api/routes/{id}/line` | 오늘 경로선 다시 받기(저장하지 않음) | 200 `{line, distanceM, durationSec}` | 404 · 503(저장 지점으로 안내) |

지켜야 할 규칙

- 화면은 지점을 만들어 보내지 않는다. `candidateId`(`candidate-0`·`candidate-4`·`candidate-10`)와 이름(1~30자)만 보낸다.
- 경로와 지점은 한 번에 모두 저장되거나 모두 저장되지 않는다. 거부된 요청 뒤에는 저장 경로가 늘지 않는다.
- 지점 좌표·이름은 공공자료 원본 값이다(TMAP 좌표가 아님). `guideSource`는 지금 `TEMPLATE`(코드가 만든 기본 안내문)뿐이다.

### A-2. 위치·거리 계산 함수 — `static/js/guide-geo.js`

서버 `GeoLine`과 같은 평면 근사를 써서 화면과 서버의 `alongM`이 같은 값이 되게 했다. 브라우저에서는 `window.GuideGeo`로 쓴다.

| 함수 | 입력 → 출력 |
|---|---|
| `distanceM(a, b)` | 두 `{lat,lng}` 사이 거리(m) |
| `prepareLine(line)` | `GET /line`의 `line` → 계산 준비된 선(`lengthM` 포함) |
| `locate(prepared, p)` | 현재 위치 → `{distanceM: 선까지 거리, alongM: 출발부터 따라간 거리}` |
| `step(points, passed, position, prepared, accuracyM)` | 안내 상태 한 번 계산 → `{state, message, next, toNextM, newlyArrived}` |

`step`의 상태와 기준값

| state | 언제 | message |
|---|---|---|
| `WEAK_SIGNAL` | 위치 정확도가 50m보다 나쁨 | 위치가 정확하지 않아요… |
| `OFF_ROUTE` | 경로선에서 40m 넘게 떨어짐(경로선이 있을 때만) | 경로를 벗어났어요. 멈춰서 지도의 선을 확인해요. |
| `ARRIVED` | 아직 안 지난 지점 20m 안. 앞에서 놓친 지점도 함께 지난 것으로 넘김 | 도착한 지점의 `guideText` |
| `WALKING` | 그 밖 | 다음 안내까지 약 ○○m (10m 단위) |
| `DONE` | 모든 지점을 지남 | 안내 지점을 모두 지났어요. |

시험: `node --test src/test/js/guide-geo.test.js` (8개 통과, 외부 의존 없음). 기준값(20m·40m·50m)은 파일 위쪽 상수라 현장 시험 뒤 바꿀 수 있다.

### A-3. 저장 경로 응답 예시

[20261110_저장경로응답예시_v1.json](examples/20261110_저장경로응답예시_v1.json)에 저장 → 목록 → 상세 → 오늘 경로선 → 남의 경로(404) → 꾸민 후보(400) 순서로 실제 서버 응답이 들어 있다. 상세의 지점 하나는 이렇게 생겼다.

```json
{ "seq": 2, "kind": "CROSSWALK", "name": "", "reason": "CROSSING",
  "lat": 37.5986733, "lng": 127.1027495, "alongM": 243, "signalStatus": "UNKNOWN",
  "source": "서울시 교통안전시설물 횡단보도 OA-15554", "originalId": "06-0000026667",
  "guideText": "횡단보도예요. 멈춰서 신호와 양쪽을 확인하고 건너요.", "guideSource": "TEMPLATE" }
```

- `reason`: `CROSSING`(실제로 건너는 횡단보도) · `TURN`(꺾는 곳) · `GAP`(200m 넘는 간격을 채운 지점)
- `kind`: `CROSSWALK` · `SCHOOL` · `CCTV` · `EMERGENCY_BELL` 넷만 안내 지점이 된다
- `signalStatus`: 횡단보도만 `ESTIMATED`(추정) 또는 `UNKNOWN`(미확인). 다른 종류는 `null`

### A-4. AI 안내문 입력 자료 (11주차 AI 문장 다듬기용)

AI에는 지점마다 아래 값만 넘긴다. 좌표·원본 ID는 문장에 필요 없으니 넘기지 않는다.

```json
{
  "routeName": "망우초 가는 길",
  "points": [
    { "seq": 1, "kind": "EMERGENCY_BELL", "reason": "GAP",      "name": "",               "signalStatus": null,      "isLast": false, "templateText": "안전비상벨이 있는 곳을 지나요. 위험할 때 누르는 벨이에요." },
    { "seq": 2, "kind": "CROSSWALK",      "reason": "CROSSING", "name": "",               "signalStatus": "UNKNOWN", "isLast": false, "templateText": "횡단보도예요. 멈춰서 신호와 양쪽을 확인하고 건너요." },
    { "seq": 3, "kind": "SCHOOL",         "reason": "TURN",     "name": "서울망우초등학교", "signalStatus": null,      "isLast": true,  "templateText": "서울망우초등학교 쪽에서 길을 꺾어요. 지도의 선을 보고 따라가요. 거의 다 왔어요!" }
  ]
}
```

AI 출력 검사 규칙(통과 못 하면 `templateText`를 그대로 쓴다). 기본 안내문 `TemplateGuide`와 같은 규칙이다.

1. 지점 수와 `seq`가 입력과 같다. 한 지점에 한 문장 묶음, 행동은 하나.
2. 횡단보도 문장에는 '멈춰'와 '신호'·'양쪽' 확인이 들어 있다.
3. 신호가 있다고 가정하는 말을 쓰지 않는다: '초록불', '파란불', '신호가 바뀌면 바로' 등.
4. '안전한 길', '위험한 길', 점수·등급처럼 안전을 판정하는 말을 쓰지 않는다.
5. 입력에 없는 장소 이름을 만들지 않는다. 이름은 지점마다 최대 하나.
6. 아이에게 말하듯 '-요'체, 한 문장 40자 안팎.

## B. 정강태: 시험 계정과 요청 예시

### B-1. 시험 계정 만들기

공용 계정과 비밀번호는 저장소에 두지 않는다. 각자 로컬(H2)이나 시험 서버에서 아래처럼 만든다. 비밀번호는 10~72자, 아이디는 영어 소문자·숫자·`_`·`-` 4~30자.

| 용도 | 아이디 예 | 쓰는 곳 |
|---|---|---|
| 경로 주인 | `qa_parent1` | 저장·목록·상세·경로선 |
| 다른 회원 | `qa_parent2` | 남의 경로 조회가 404인지 |

### B-2. 요청 예시 (curl, 로컬 `http://localhost:8081`)

POST에는 CSRF 토큰이 필요하다. 쿠키 값이 아니라 `GET /api/auth/csrf` 응답의 `token`을 `X-XSRF-TOKEN` 헤더로 보낸다(화면 `auth.js`와 같은 방식). 쿠키 파일(`jar.txt`)로 세션을 이어 간다.

```bash
B=http://localhost:8081; J=jar.txt
csrf() { curl -s -c $J -b $J $B/api/auth/csrf | python3 -c 'import sys,json;print(json.load(sys.stdin)["token"])'; }
# 0) CSRF 토큰 받기
T=$(csrf)

# 1) 가입 (201, 이미 있으면 409)
curl -s -c $J -b $J -H "X-XSRF-TOKEN: $T" -H 'Content-Type: application/json' \
  -d '{"loginId":"qa_parent1","password":"<10자 이상>","nickname":"시험 보호자","age14OrOlder":true}' $B/api/auth/signup

# 2) 로그인 (form 방식, 200 {"authenticated":true}). 로그인 뒤 토큰이 바뀌므로 다시 받는다
curl -s -c $J -b $J -H "X-XSRF-TOKEN: $T" --data-urlencode username=qa_parent1 --data-urlencode 'password=<비밀번호>' $B/api/auth/login
T=$(csrf)

# 3) 근거 분석
curl -s -c $J -b $J -H "X-XSRF-TOKEN: $T" -H 'Content-Type: application/json' \
  -d '{"start":{"lat":37.59867,"lng":127.1},"end":{"lat":37.5998,"lng":127.1036}}' $B/api/routes/evidence

# 4) 저장 (201 {"id":…})
curl -s -c $J -b $J -H "X-XSRF-TOKEN: $T" -H 'Content-Type: application/json' \
  -d '{"start":{"lat":37.59867,"lng":127.1},"end":{"lat":37.5998,"lng":127.1036},"candidateId":"candidate-0","name":"망우초 가는 길"}' $B/api/routes

# 5) 목록 · 상세 · 오늘 경로선
curl -s -b $J $B/api/routes
curl -s -b $J $B/api/routes/1
curl -s -b $J $B/api/routes/1/line
```

실제 TMAP을 부르려면 `.env`에 `TMAP_APP_KEY`가 있어야 한다. 하루 호출 한도(`TMAP_DAILY_LIMIT`, 기본 950)가 있고, 같은 출발·도착은 당일 캐시를 써서 호출이 늘지 않는다.

한 번에 돌리는 스크립트: `scripts/api_smoke.sh http://localhost:8081` — 새 시험 계정 둘을 만들어 가입·로그인 → 익명 저장 401 → 꾸민 후보 400 → 근거 분석 → 저장 → 본인 200·남의 경로 404까지 확인한다. 비밀번호는 실행 때마다 새로 만든다. CI에서도 실행 파일을 띄워 이 스크립트를 돌린다(TMAP 키가 없어 근거 분석 503에서 멈추는 것이 정상).

### B-3. 꼭 확인할 실패 사례

| 경우 | 요청 | 기대 결과 |
|---|---|---|
| 로그인 안 함 | 쿠키 없이 `POST /api/routes` | 401, 저장 0건 |
| 꾸민 후보 | `candidateId":"candidate-99"` 또는 `"../etc"` | 400 '선택한 후보가 올바르지 않습니다.' |
| 이번에 없는 후보 | 세 옵션이 같은 길로 합쳐졌을 때 `candidate-4` | 400 '후보를 다시 조회해 주세요' |
| 이름 오류 | `"name":" "` 또는 31자 | 400 |
| 서울 밖·같은 좌표 | 출발=도착, 또는 서울 밖 좌표 | 400 |
| 주변에 공공자료 없음 | 지원 12개 구 밖 경로 | 422, 저장 0건 |
| 남의 경로 | `qa_parent2`로 `GET /api/routes/1`, `/1/line` | 404 (없는 경로와 구분하지 않음) |
| TMAP 실패 | 키 없음·한도 초과 | 저장 503, `/line`은 503 '저장한 안내 지점으로 안내해요' |
| 경로선 미저장 | DB `saved_route`·`saved_route_point` 열 확인 | `line`·`distance_m`·`duration_sec` 열 없음 |

자동 시험으로 이미 확인한 것: `SavedRouteFlowTests`(저장·본인만 조회·오늘 경로선·꾸민 후보·익명·지점 없음).
