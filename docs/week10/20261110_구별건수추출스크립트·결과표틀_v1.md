## 1. 스크립트가 하는 일

적재 파일(`supported-districts.json.gz`)에서 구 × 자료 종류(6종) 72칸마다 다음 값을 뽑는다.

| 열 | 뜻 |
|---|---|
| 적재 파일 행 수 | 정제가 끝나 적재 파일에 들어간 행 수 |
| DB 행 수 | 실제 DB `facility` 행 수 (`--db-csv` 또는 `--coverage-json`을 줄 때만 채움) |
| 일치 | 위 두 값이 같으면 '일치', 다르면 '불일치' |
| 위도·경도 범위 | 그 칸 좌표의 최소~최대. 다른 구 범위와 크게 겹치면 구 배정 오류를 의심한다 |
| 출처 · 원본 내려받은 날짜 · 기준일 범위 | 출처표기용. 원본에 기준일이 없으면 '원본에 없음' |
| 상태 | 1건 이상 '적재', 0건 '자료 부족' |

또 자료 종류별 합계와 자료 부족 구, 구별 사고 다발 지역(면) 개수, 좌표 문제로 넣지 않은 원본 행을 함께 적는다.

## 2. 실행 방법

```bash
# 적재 파일만으로 (DB 칸은 비어 있음)
python3 scripts/district_counts.py --out build/district-counts

# 운영 MySQL 행 수까지 넣기
mysql -B -e "source scripts/district_counts.sql" safe_school_road | tr '\t' ',' > db-counts.csv
python3 scripts/district_counts.py --db-csv db-counts.csv --out build/district-counts

# 서버 적재 현황 응답으로 넣기 (로그인한 세션으로 GET /api/data/coverage 저장)
python3 scripts/district_counts.py --coverage-json coverage.json --out build/district-counts
```

결과로 `<out>.md`(결과표)와 `<out>.csv`(엑셀로 열 수 있게 UTF-8 BOM)가 생긴다.

이번 결과표의 DB 행 수는 CI의 H2 DB에 실제 적재한 뒤 센 값이다([20261110_DB구별건수_v1.csv](examples/20261110_DB구별건수_v1.csv)). 60칸이 모두 일치했고, 자료 부족은 12칸(12개 구 보안등)이었다.

## 3. 4-11-03 결과표 틀 (유준서 작성용)

스크립트 결과에 '원본 행 수'·'운영 DB 행 수'·'차이 이유' 세 열을 사람이 채워 넣는다. '원본 행 수'는 적재 파일에는 없는 값이라, 원본 파일을 열어 구별로 세야 한다.

| 구 | 자료 종류 | 원본 행 수 | 적재 파일 행 수 | 운영 DB 행 수 | 차이 이유 | 좌표 범위 | 출처 / 기준일 | 상태 |
|---|---|---:|---:|---:|---|---|---|---|
| 중랑구 | 횡단보도 | (원본에서 셈) | 1985 | (운영 DB) | | 37.57085~37.62063 / 127.07132~127.11788 | OA-15554 / 원본에 없음 | 적재 |
| 중랑구 | 보안등 | (원본에서 셈) | 0 | 0 | 좌표 행 없음 | - | 전국보안등정보표준데이터 | **자료 부족** |
| … | … | | | | | | | |

작성 규칙

- 0건은 빈칸으로 두지 말고 상태를 **자료 부족**으로 적는다.
- 원본 행 수와 적재 파일 행 수가 다르면 '차이 이유'를 적는다(예: 좌표 없음, 중복, 다른 구 좌표).
- 어린이보호구역은 '대상시설 위치(점)'이고 구역 경계가 아니라고 표 아래에 적는다.
- 신호 칸을 만들 경우 '추정 / 미확인'만 쓴다. 확정 자료는 없다.
